# 汎用(未対応言語・レガシー向け)

専用の参照ファイルがない言語(COBOL、PL/SQL、VB.NET、Rust、Delphi、独自DSLなど)で使う。新しい言語で繰り返し使うなら、このファイルと同じ見出し構成で `references/stacks/<名前>.md` を追加する。

## 機械的に取れる情報

- **ファイル構成**: `find . -type f | sed 's/.*\.//' | sort | uniq -c | sort -rn` で拡張子分布を見る
- **エントリポイントの手がかり**: `main`、`Main`、`PROCEDURE DIVISION`、`CREATE PROCEDURE`、`handler`、`job`、`batch` などを grep する
- **データ定義**: DDL(`CREATE TABLE`)、コピー句(COBOL)、レコード定義、スキーマファイル
- **ジョブ定義**: JCL、cron、シェルスクリプト、ジョブスケジューラの定義ファイル
- **設定**: `.ini`、`.properties`、`.yaml`、環境変数の参照箇所
- **呼び出し関係**: ctags / universal-ctags、tree-sitter が使えるならシンボル一覧を作る

## 読む順番

1. ジョブ定義・起動スクリプト(何が、いつ、どの順で動くか)
2. データ定義(何を持っているか)
3. エントリポイントから下へ

## 業務ルールが潜みやすい場所

- 定数定義、コード値の分岐(`EVALUATE`、`CASE`、`IF` の連鎖)
- ストアドプロシージャ、トリガー、ビュー(アプリ側に見えないロジック)
- 帳票・CSV出力の整形処理(丸め、桁、日付書式)

## 落とし穴

- ロジックがDB側(ストアド、トリガー)に寄っている場合、アプリコードだけ読むと仕様が欠ける
- 文字コード(Shift_JIS、EBCDIC)。読めない場合は変換してから読む
- 外部のジョブスケジューラにしか起動順が書かれていないことがある → 未確認事項に積む
