# Sub-issue指示テンプレスキル

このスキルは、親Issueから1件のSub-issueを切り出し、実装エージェントに渡す指示文を型どおりに書く際に使用します。指示文の型を毎回同じ精度で再現し、実装エージェントが自分で範囲を判断しなくてよい状態を作ります。

## When to Use

- 親Issueから、実装に渡すSub-issueを1件切り出すとき
- Sub-issueの指示文（範囲・やらないこと・触ってよい/いけないファイル・完了条件）を書くとき
- 既存のSub-issueの指示文が曖昧で、書き直しを頼まれたとき

## Instructions

### 指示文の5項目

次の5項目を、この順で書きます。項目を減らしたり、順番を変えたりしません。

1. **範囲**: 1PR・1Sub-issueに収まる大きさかを一文で示す
2. **やらないこと**: 範囲外に見えやすい高度化・拡張・関連作業を明記する。「なぜ無いのか」があとから疑問にならないようにする
3. **触ってよいファイル**: 実装対象のファイル・ディレクトリを列挙する
4. **触ってはいけないファイル**: 契約や責務の境界を越えないよう、明示的に除外するファイル・ディレクトリを列挙する
5. **完了条件**: テストやコードで判定できる形で書く。「動くこと」のような感覚的な表現は避け、YES/NOで判定できる条件にする

### 完了条件の書き方

完了条件は、次のいずれかで判定できる形にします。

- 特定の操作をすると、特定の結果が返る（例: 「検索ボックスに文字を入力すると、一致する行だけが表示される」）
- テストが通る
- 特定のステータス・値になる

「正しく動作すること」「問題なく表示されること」のような、判定者によって結果が変わる書き方は避けます。

### 出力の型

```text
範囲: (1PR・1Sub-issueに収まる大きさの説明)
やらないこと: (範囲外に見えやすい作業の列挙)
触ってよいファイル: (対象ファイル・ディレクトリ)
触ってはいけないファイル: (除外するファイル・ディレクトリと理由)
完了条件: (YES/NOで判定できる条件)
```

### 親Issueとの関係

Sub-issueは、親Issueの完了条件の一部を担います。Sub-issueの完了条件が親Issueのどの完了条件に対応するかを本文かコメントに残しておくと、あとから追跡しやすくなります。

GitHub上でSub-issue関係を実際に登録する場合、Issue本文にリンクを書くだけでは親子関係になりません。GitHub CLIやAPI経由で明示的に登録します。

https://docs.github.com/en/issues/tracking-your-work-with-issues/using-issues/adding-sub-issues

## よくある問題

### 完了条件が曖昧なまま先に進んでしまう

「動くこと」のような感覚的な完了条件は、実装後にPASS/FAILの判定がぶれます。判定者が変わっても同じ結果になる条件に書き直してから次に進みます。

### 「やらないこと」を書き忘れる

やらないことを書かないと、実装エージェントが範囲外まで作り込みがちです。範囲に近い作業ほど、明示的に「やらない」と書きます。
