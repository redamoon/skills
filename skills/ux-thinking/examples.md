# UX 思考 — 会話と成果物の例

ワイヤーの前に質問して仕様を固める入口です。エージェントは枠を描かず、質問 → 仕事定義 → 画面の役割、の順で止めます。

## 依頼

> 予約機能のワイヤーを作ってほしい。カレンダーアプリに「予約」を足す。

## 1. 成果物: 質問

仕事が固定されていないので、画面案は出さず、足りない項だけを一度に聞きます。

```markdown
ワイヤーの前に、仕事定義を固めたいです。分かっている範囲で答えてください。

1. 誰が、何を終わらせたいですか。終わったと感じる瞬間はどこですか
   （予約画面を開くこと自体ではない）
2. 何がきっかけで、急いでいますか。途中で中断されますか
3. 初めてですか、毎日ですか。両方ありますか
4. 既存の画面・言葉・制約はありますか
5. 今回欲しいのは、仕事定義、画面の役割、既存の診断、コピー案のどれですか
```

### ユーザーの答え（例）

- 保護者が、週末の家族の予定を一件、相手に確定してほしい。終わったと感じるのは、相手が「行く」と返して、自分のカレンダーに確定で載ったとき
- 金曜の夜に、メッセージを見ながら入れる。子どもが話しかけて中断される
- 初めてが多い。毎週使う人もいる
- いまはカレンダー閲覧だけ。社内では「ワークスペース」と呼んでいるが、ユーザーは「カレンダー」と言っている。スマホ Web
- まず仕事定義と、そのあと画面の役割

## 2. 成果物: 仕事定義

ここで一度止め、「これで画面の役割に進めてよいか」を確認します。

```markdown
## 仕事定義
- 誰: 家族の予定を入れる保護者。カレンダーは見慣れている。予約という言葉は使っていない
- 状況: 金曜の夜、チャットを見ながら。途中で中断される
- 終わらせたい変化: 候補の日時が、相手の承諾つきで自分のカレンダーに確定して載る
- 成功の瞬間: 確定した一件がカレンダーに見え、相手にも届いていると分かる
- 制約: スマホ Web。既存は閲覧のみ。ユーザーの言葉は「カレンダー」「予定」。中断される
- 一文: When 金曜の夜に家族の予定を決めたいとき, I want to 一件を相手に確定してもらう, so I can 週末の動きをカレンダーで見られる

## 旅（出来事）
1. きっかけ: 相手から「土曜空いてる？」とメッセージが来る
2. 期待: 土曜の候補を入れて、相手が承諾し、自分のカレンダーに載る
3. 最初の接触: 空のカレンダー（または既存の予定）を開く。「予定を入れる」が一目で分かる
4. 最初の成功: 日時と相手が入り、依頼が送れる
5. 迷いどころ: 「ワークスペースを作る」など、予定以外の言葉が出ると止まる
6. 失敗したとき: 入力中に中断、通信切れ、相手が断る、権限がない
7. 完了の確認: 「確定した」とカレンダー上で見える。相手にも届いたと分かる
8. 完了後: 同じ相手でもう一件、または変更・取り消し

## まだ開いている問い
- 相手は同じアプリにいるか、リンクだけで承諾するか

この内容で画面の役割に進めてよいですか。
```

## 3. 成果物: 画面の役割

仕事定義が合意されたあとに出します。レイアウトではなく、各面が何の仕事かです。これがワイヤーの入力になります。

```markdown
## 画面の役割

### 面1: カレンダー（入口）
- この面の仕事: 最初の予定を入れる、または確定済みを見る
- 次の一手: 予定を入れる（空のとき） / 予定を開く（あるとき）
- 出すもの: 日付、既存の予定、主ボタン
- 出さないもの: ワークスペース作成、チーム名、タイムゾーン
- 必要な状態: 空（入口）、読込、成功（予定あり）、権限不足

### 面2: 予定を入れる
- この面の仕事: 日時と相手を入れて、確定の依頼を送る
- 次の一手: 確定の依頼を送る
- 出すもの: 日付、時刻、相手、任意の一言
- 出さないもの: チーム設定、繰り返しの詳細（初回は一件）
- 必要な状態: 入力中、読込、入力エラー、システムエラー、中断（下書き再開）

### 面3: 確定を待つ / 確定した
- この面の仕事: 依頼が届き、承諾または断りが返ったことを知る
- 次の一手: 待つ / 確定した予定をカレンダーで見る / 断りなら別の日時を入れる
- 出すもの: いまの状態（待ち・確定・断り）、カレンダーへ戻る
- 出さないもの: 新しい設定画面
- 必要な状態: 待ち、部分成功（相手未読）、成功、断り、中断
```

ユーザーがこのあと「Figma でワイヤーにして」と言った場合に限り、面×状態の一覧を示してから低忠実度フレームを起こします。

## 4. 成果物: Figma への引き渡し

```markdown
この役割で、次のフレームを低忠実度で起こします。仕様にない面は足しません。

| フレーム | 主ボタン | 置くもの | 置かないもの |
|----------|----------|----------|--------------|
| Calendar / Empty | 予定を入れる | 日付、空の説明 | ワークスペース作成 |
| Calendar / Loaded | 予定を入れる | 日付、既存の予定 | チーム名 |
| Put event / Editing | 確定の依頼を送る | 日付、時刻、相手、任意の一言 | 繰り返しの詳細 |
| Put event / Error | 確定の依頼を送る | フィールド横の直し方、入力は残す | 空のフォームへのリセット |
| Wait / Pending | （待ち。カレンダーへ戻る） | いまの状態 | 新しい設定 |
| Wait / Confirmed | カレンダーで見る | 確定した一件 | — |

この一覧で Figma に起こしてよいですか。ファイルは新規ですか、既存ですか。
```

Figma が使えない環境では、同じ表をテキストの画面スケッチとして出して止めます。

## この例でやっていないこと

- 最初からカレンダー画面のワイヤーを描く
- 仕様の前に Figma を開く
- 「ワークスペース作成」を面1の主操作にする
- 保護者の名前や年齢のペルソナを創作する
- ヒューリスティックの点数表を成果物にする
- 成功画面だけ描いて、空とエラーを省略する
