# UX 思考 — 会話と成果物の例

ワイヤーの前に質問して仕様を固める入口です。エージェントは枠を描かず、質問 → 仕事 → 画面の役割 → テキストスケッチ、の順で止めます。Figma はスケッチのあとです。

## 依頼

> 予約機能のワイヤーを作ってほしい。カレンダーアプリに「予約」を足す。

## 1. 成果物: 質問

仕事が固定されていないので、画面案は出さず、足りない項だけを一度に聞きます。

```markdown
ワイヤーの前に、仕事を固めたいです。分かっている範囲で答えてください。

1. 誰が、何を終わらせたいですか。終わったと感じる瞬間はどこですか
   （予約画面を開くこと自体ではない）
2. 何がきっかけで、急いでいますか。途中で中断されますか
3. 頻度はどれですか（初めて／毎回。毎回なら毎日・毎週・毎月など）。高い側と低い側はありますか
4. 既存の画面・言葉・制約はありますか。一人か共有か、どの端末か。同じ仕事が別の場所に残りますか
5. 今回欲しいのは、仕事、画面の役割、テキストスケッチ、既存の診断、コピー案のどれですか
```

### ユーザーの答え（例）

- 保護者が、週末の家族の予定を一件、相手に確定してほしい。終わったと感じるのは、相手が「行く」と返して、自分のカレンダーに確定で載ったとき
- 金曜の夜に、メッセージを見ながら入れる。子どもが話しかけて中断される
- 初めてが多い。毎週使う人もいる
- いまはカレンダー閲覧だけ。社内では「ワークスペース」と呼んでいるが、ユーザーは「カレンダー」と言っている。スマホ Web
- まず仕事と、そのあと画面の役割。テキストスケッチも欲しい

## 2. 成果物: 仕事

ここで一度止め、「これで画面の役割に進めてよいか」を確認します。

```markdown
## 仕事
- 誰: 家族の予定を入れる保護者。カレンダーは見慣れている。予約という言葉は使っていない
- 状況: 金曜の夜、チャットを見ながら。途中で中断される
- 終わらせたい変化: 候補の日時が、相手の承諾つきで自分のカレンダーに確定して載る
- 成功の瞬間: 確定した一件がカレンダーに見え、相手にも届いていると分かる
- 制約: スマホ Web。既存は閲覧のみ。ユーザーの言葉は「カレンダー」「予定」。中断される
- 一文: When 金曜の夜に家族の予定を決めたいとき, I want to 一件を相手に確定してもらう, so I can 週末の動きをカレンダーで見られる

## シナリオ
1. きっかけ: 相手から「土曜空いてる？」とメッセージが来る
2. 期待: 土曜の候補を入れて、相手が承諾し、自分のカレンダーに載る
3. 最初の接触: 空のカレンダー（または既存の予定）を開く。「予定を入れる」が一目で分かる
4. 最初の成功: 日時と相手が入り、依頼が送れる
5. 迷いどころ: 「ワークスペースを作る」など、予定以外の言葉が出ると止まる
6. 失敗したとき: 入力中に中断、通信切れ、相手が断る、権限がない
7. 完了の確認: 「確定した」とカレンダー上で見える。相手にも届いたと分かる
8. 完了後: 同じ相手でもう一件、または変更・取り消し

## まだ開いている問い
- 相手は同じアプリにいるか、リンクだけで承諾するか

この内容で画面の役割に進めてよいですか。
```

## 3. 成果物: 画面の役割

仕事が合意されたあとに出します。レイアウトではなく、各面が何の仕事かです。次の成果物はテキストスケッチです。

```markdown
## 画面の役割

### 面1: カレンダー（入口）
- この面の仕事: 最初の予定を入れる、または確定済みを見る
- 次の一手: 予定を入れる（空のとき） / 予定を開く（あるとき）
- 出すもの: 日付、既存の予定、主ボタン
- 出さないもの: ワークスペース作成、チーム名、タイムゾーン
- 必要な状態: 空（入口）、読込、成功（予定あり）、権限不足

### 面2: 予定を入れる
- この面の仕事: 日時と相手を入れて、確定の依頼を送る
- 次の一手: 確定の依頼を送る
- 出すもの: 日付、時刻、相手、任意の一言
- 出さないもの: チーム設定、繰り返しの詳細（初回は一件）
- 必要な状態: 入力中、読込、入力エラー、システムエラー、中断（下書き再開）

### 面3: 確定を待つ / 確定した
- この面の仕事: 依頼が届き、承諾または断りが返ったことを知る
- 次の一手: 待つ / 確定した予定をカレンダーで見る / 断りなら別の日時を入れる
- 出すもの: いまの状態（待ち・確定・断り）、カレンダーへ戻る
- 出さないもの: 新しい設定画面
- 必要な状態: 待ち、部分成功（相手未読）、成功、断り、中断
```

ユーザーが「各面の中身を」「テキストで画面を」と言ったら、役割を入力にテキストスケッチを出す。Figma には、スケッチのあとで渡す。

## 4. 成果物: テキストスケッチ

配置は書かない。主ボタンは結果の動詞。状態は別ブロック。

```markdown
## テキストスケッチ

### 面1 / 空
- 見出し: まだ予定がない
- 本文: 最初の一件を入れると、週末の動きが見える
- 主ボタン: 予定を入れる
- 入力: なし
- 出さないもの: ワークスペース作成、チーム名

### 面1 / 成功（予定あり）
- 見出し: カレンダー
- 本文: 確定した予定が見える
- 主ボタン: 予定を入れる
- 入力: なし
- 出さないもの: タイムゾーン

### 面2 / 入力中
- 見出し: 予定を入れる
- 本文: 日時と相手を入れて、確定の依頼を送る
- 主ボタン: 確定の依頼を送る
- 入力: 日付、時刻、相手、任意の一言
- 出さないもの: 繰り返しの詳細

### 面2 / 入力エラー
- 見出し: 予定を入れる
- 本文: 直せば依頼を送れる。入力は残している
- 主ボタン: 確定の依頼を送る
- 入力: 日付、時刻、相手（残す）
- フィールド横: 終了が開始より前。終了をあとへずらす
- 出さないもの: 空フォームへのリセット

### 面3 / 待ち
- 見出し: 確定を待っている
- 本文: 相手に依頼が届いている。カレンダーに戻ってよい
- 主ボタン: なし（待つことが仕事。カレンダーへ戻るは副）
- 入力: なし
- 出さないもの: 新しい設定

### 面3 / 成功
- 見出し: 確定した
- 本文: この予定がカレンダーに載っている。相手にも届いた
- 主ボタン: カレンダーで見る
- 入力: なし
```

## 5. 成果物: Figma への引き渡し

テキストスケッチのあと、「Figma でワイヤーにして」と言われたら、面×状態の一覧を同じターンで出してから低忠実度フレームを起こす。ファイル URL が付いていても、一覧を省略しない。

```markdown
このスケッチで、次のフレームを低忠実度で起こします。仕様にない面は足しません。

| フレーム | 主ボタン | 置くもの | 置かないもの |
|----------|----------|----------|--------------|
| Calendar / Empty | 予定を入れる | 日付、空の説明 | ワークスペース作成 |
| Calendar / Loaded | 予定を入れる | 日付、既存の予定 | チーム名 |
| Put event / Editing | 確定の依頼を送る | 日付、時刻、相手、任意の一言 | 繰り返しの詳細 |
| Put event / Error | 確定の依頼を送る | フィールド横の直し方、入力は残す | 空のフォームへのリセット |
| Wait / Pending | （待ち。カレンダーへ戻る） | いまの状態 | 新しい設定 |
| Wait / Confirmed | カレンダーで見る | 確定した一件 | — |

この一覧で Figma に起こします。文言はテキストスケッチのまま。端末はスマホ 390。ファイルは新規ですか、既存ですか。
```

Figma が使えないときは、テキストスケッチで止める。フレーム一覧表でスケッチの代わりをしない。

## 6. 数字の仕事（短い例）

入口が「家計簿アプリをつくりたい」でも、機能カタログには入らない。見たい数字が空なら、役割の前に聞く。

```markdown
数字を見て終わる仕事なので、同じターンで足します。

- 見たい数字は何ですか。材料は何ですか。材料はいつ揃いますか
```

答えの例: 支払と収入の差額。材料はカード請求・家賃・引き落としと収入。だいたい毎月12日。ATM では口座の差額と手持ちの現金の合算を見る。

仕事では面のラベルを先に発明しない。式が「口座の差額 + 手持ちの現金 = 合算」と分かるまで、「入れる金額」など推測した名前で面を固定しない。

シナリオは二本辿る。

- 低い側: 初回の12日。スプレッドシートから移り、口座の差額が一度確定する
- 高い側: 翌月の同じ12日。いつもの収入は入ったまま、支払だけ更新する
- 完了後: ATM で手持ちの現金を足し、合算を見る（端末が変わるので面を分ける）

開いている問いへの回答が来たら、先に仕事を更新する。当初の成果物に画面の役割が含まれ、問いが全て埋まったら役割を出してよい。「これでよい」の沈黙は合意にしない。

## この例でやっていないこと

- 最初からカレンダー画面のワイヤーを描く
- 仕様の前に Figma を開く
- 「ワークスペース作成」を面1の主操作にする
- 保護者の名前や年齢のペルソナを創作する
- ヒューリスティックの点数表を成果物にする
- 役割から Figma に飛ばし、テキストスケッチを省略する
- 成功画面だけ描いて、空とエラーを省略する
- 式が空のまま「入れる金額」などの面名を固定する
- ファイル URL だけでフレーム一覧を省略する
- 低忠実度ワイヤーに Material などの購読ライブラリを載せる
