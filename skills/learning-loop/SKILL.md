# Learning Loopスキル

このスキルは、同じ指摘・訂正が繰り返されたときに、文書を増やす前にまず機械で防げないかを検討し、優先順位に沿って仕組み化する際に使用します。

## When to Use

- 同じ指摘や訂正が2回以上繰り返されたとき
- レビューで見送った軽微な指摘のうち、再発したものを棚卸しするとき
- 「また同じことを言われた」「再発防止したい」と依頼されたとき

## Instructions

### 優先順位

実際に再発が確認された指摘だけを対象に、次の優先順で仕組み化します。上位の手段で防げるなら、下位の手段を増やす必要はありません。

1. **テスト・lint**: CIのジョブ、スキーマ・ポリシーの検査など、機械的に落とせる形にする
2. **ルール文書**: AGENTS.mdやdocsに追記する。手順ならAGENTS.md、事実（ドメイン知識・規約）ならdocsに置く
3. **SKILL**: 指示テンプレのような手順書として、SKILLに落とし込む

### 候補にする条件

- 実際に2回以上再発したものだけを候補にする
- まだ観測していない指摘を先回りしてルール化・SKILL化しない
- レビューで「提案」や軽微指摘として見送った項目のうち、再発したものを優先する

### 運用の流れ

1. 再発した指摘をIssueとして起票する
2. 優先順位に従い、テスト・lintで防げないかをまず検討する
3. 防げない場合、手順かドメイン知識かを判断し、ルール文書に追記する
4. 頻繁に使う手順であれば、SKILLとしてファイル化する
5. 通常の開発フローに乗せてクローズする

## よくある問題

### 観測前に予防的にルールやSKILLを増やしてしまう

まだ一度も起きていない失敗を想定してSKILLやルールを先回りして増やすと、文書だけが肥大化し、実際には読まれません。実際に再発したものだけを対象にします。

### ルール文書とSKILLの置き場所が混ざる

「全員が毎回知るべき前提や事実」はルール文書（AGENTS.md/docs）に、「毎回同じ手順を再現するためのチェックリスト」はSKILLに置きます。混ぜて置くと、次に同じ場面が来たときにどちらを見ればよいか分からなくなります。
